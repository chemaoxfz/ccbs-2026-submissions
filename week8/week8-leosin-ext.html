The computational loop optimizes the predictor; the experimental loop optimizes the protein

Leo Sin (施延庆) · Week 8, lectures 15–16 · CCBS 2026 · 2026-11-02

In one sentence: lecture 15’s warning that a design “success rate” is meaningless without its denominator becomes quantitative once you write the two feedback loops down — a compute-only loop hill-climbs the score, so its final designs sit exactly where the predictor is most wrong (high score, mediocre truth), while an experimental loop that lets the assay pick the winner converges to higher true fitness with far fewer proposals.

The point I am adding

Lecture 15 framed protein design as six questions, two of which do most of the work in practice: what counts as success (success rate needs a denominator — success per designed sequence? per tested variant? per round?) and where the feedback loop closes. A computational design cycle (ProteinMPNN-style: propose → score in silico → retrain) closes the loop on the predictor’s score; a directed-evolution cycle (mutagenesis → assay → pick winner) closes it on measured fitness1,2. Everyone intuits these drift apart; I wanted a minimal quantitative toy where the drift is visible and measurable, because that is what decides which loop a project should buy.

The toy: a 10-site walk from wild type, mutation i adding an independent Gaussian fitness contribution but each extra mutation also paying a destabilisation cost (folding epistasis) — so true fitness peaks at a modest mutational distance. The predictor reports score s = f + noise + β(d/L): near WT it is roughly right, but it drifts systematically upward as designs move away from the training region (extrapolation bias β > 0). Then:

Loop A (compute-only): 40 greedy steps accepting any neighbouring variant with a higher score. Loop B (ML-assisted directed evolution, in the spirit of low-N pick-and-validate1,3): 6 rounds, each proposing 4 variants ranked by the predictor but advancing only the variant the assay says is best. Averaged over 60 seeded landscapes:

loop A: final score 0.74, but true fitness only 0.60, at distance d ≈ 3.6 from WT    |    loop B: true fitness 0.75 at d ≈ 2.7

Loop A reads as the better “designer” by its own metric — and is the worse one by the only metric the cell cares about. Its final score overstates truth by ≈ 0.15, which is precisely the size of the noise-plus-bias term it has been selecting for. That is the denominator point in disguise: reported “success rates” from compute-only loops measure the predictor’s optimism, not protein quality2; loops that close through the assay convert the same predictor into a search heuristic rather than an oracle — exactly the division of labour between model and experiment that made low-N directed evolution work1 and that classical evolution loops never needed a predictor for4.

Work it

Simulation code (Python, standard library only) 
#!/usr/bin/env python
# -*- coding: utf-8 -*-
"""
week8 ext simulation: the computational loop optimizes the predictor,
the experimental loop optimizes the protein.

Toy fitness landscape: L=10 sites, each mutated away from WT adds an
independent Gaussian contribution (random per landscape, seed-fixed).
A proposal is a sequence of single mutations from WT; d = Hamming distance
from WT, f = true fitness.

Predictor score s = f + noise*xi + beta*(d/L): an imperfect model that is
biased upward for sequences far from the training region (extrapolation
bias) -- the failure mode of "success rate needs a denominator".

Loop A (compute-only feedback): greedy hill-climb on s for 40 steps.
Loop B (ML-assisted directed evolution): 6 rounds x 4 proposals/round;
proposals ranked by s among untested neighbors; the round winner is chosen
by MEASURED f (loop closes through the lab).

Outputs mean +/- band over 60 landscapes, and the cloud of loop-A
final designs in (s, f) space, as SVG path fragments.
"""
import json, random, math

L = 10
STEPS_A = 40
ROUNDS_B, PROPS = 6, 4
NOISE, BETA = 0.20, 0.50
DESTAB = 0.15      # per-mutation destabilization cost (folding epistasis)
N_LAND = 60

def make_land(rng):
    return [rng.gauss(0, 1) for _ in range(L)]  # per-site mutation effect

def true_f(effs, d):
    return sum(effs[:d]) - DESTAB * d  # f falls off for d far past optimum

def score(effs, d, rng):
    return true_f(effs, d) + rng.gauss(0, NOISE) + BETA * (d / L)

def run_A(effs, rng):
    d, traj = 0, [0.0]
    for _ in range(STEPS_A):
        cand = [score(effs, d + 1, rng) for _ in range(3)]
        if max(cand) > score(effs, d, rng):
            d += 1
        traj.append(true_f(effs, d))
    return d, traj

def run_B(effs, rng):
    d, traj = 0, [0.0]
    for _ in range(ROUNDS_B):
        # propose 4 variants around current d, ranked by predictor;
        # the round winner is chosen by MEASURED f (loop closes through the lab)
        props = sorted({min(L, d + k) for k in (1, 2, 3)} | {max(0, d - 1)},
                       key=lambda x: -score(effs, x, rng))[:PROPS]
        d = max(props, key=lambda x: true_f(effs, x))
        traj.append(true_f(effs, d))
    return d, traj

rng = random.Random(20261102)
landscapes = [make_land(random.Random(rng.randrange(2**31))) for _ in range(N_LAND)]

trajs_A, trajs_B, finals = [], [], []
for effs in landscapes:
    r2 = random.Random(rng.randrange(2**31))
    dA, tA = run_A(effs, r2)
    dB, tB = run_B(effs, r2)
    trajs_A.append(tA); trajs_B.append(tB)
    finals.append((dA, true_f(effs, dA), score(effs, dA, r2), dB, true_f(effs, dB)))

lenA = STEPS_A + 1
lenB = ROUNDS_B + 1
def band(trajs, ln):
    m = []
    lo, hi = [], []
    for t in range(ln):
        vals = sorted(tr[t] for tr in trajs)
        m.append(sum(vals) / len(vals))
        lo.append(vals[max(0, int(0.25 * len(vals)))])
        hi.append(vals[min(len(vals) - 1, int(0.75 * len(vals)))])
    return m, lo, hi

mA, loA, hiA = band(trajs_A, lenA)
mB, loB, hiB = band(trajs_B, lenB)

# SVG geometry, panel 1: x = step (0..40), y = fitness
W, H, ML, MT = 560, 340, 56, 14
def xA(t): return ML + t / STEPS_A * (W - ML - 12)
def yA(v): return MT + (1 - (v + 4) / 12) * (H - MT - 30)
def xB(r): return ML + r / ROUNDS_B * (W - ML - 12)

def path(xs, ys):
    return "M " + " L ".join(f"{x:.1f},{y:.1f}" for x, y in zip(xs, ys))

bandA = path([xA(t) for t in range(lenA)], [yA(v) for v in hiA]) + " L " + \
        " L ".join(f"{xA(t):.1f},{yA(loA[t]):.1f}" for t in reversed(range(lenA))) + " Z"
bandB = path([xB(r) for r in range(lenB)], [yA(v) for v in hiB]) + " L " + \
        " L ".join(f"{xB(r):.1f},{yA(loB[r]):.1f}" for r in reversed(range(lenB))) + " Z"
lineA = path([xA(t) for t in range(lenA)], [yA(v) for v in mA])
lineB = path([xB(r) for r in range(lenB)], [yA(v) for v in mB])

# panel 2: loop-A final designs in (s, f); WT/reference line f = s - beta*(d/L) omitted,
# just plot dots + identity-ish reference
W2 = 560
def xS(s): return ML + (s + 4) / 16 * (W2 - ML - 12)
def yF(v): return MT + (1 - (v + 4) / 12) * (H - MT - 30)
dots = " ".join(f"{xS(s):.1f},{yF(f):.1f}" for _, f, s, _, _ in finals)
meanA_f = sum(f for _, f, _, _, _ in finals) / N_LAND
meanA_d = sum(dA for dA, _, _, _, _ in finals) / N_LAND
meanB_f = sum(f for _, _, _, _, f in finals) / N_LAND
meanB_d = sum(dB for _, _, _, dB, _ in finals) / N_LAND
meanA_s = sum(s for _, _, s, _, _ in finals) / N_LAND
# final means on panel 1
finA = f"{xA(STEPS_A):.1f},{yA(meanA_f):.1f}"
finB = f"{xB(ROUNDS_B):.1f},{yA(meanB_f):.1f}"

out = {
    "meanA_f": round(meanA_f, 3), "meanA_d": round(meanA_d, 2),
    "meanB_f": round(meanB_f, 3), "meanB_d": round(meanB_d, 2),
    "meanA_s": round(meanA_s, 3),
    "mA_last3": [round(v, 2) for v in mA[-3:]],
    "mB_last3": [round(v, 2) for v in mB[-3:]],
    "svg": {"bandA": bandA, "bandB": bandB, "lineA": lineA, "lineB": lineB,
            "dots": dots, "finA": finA, "finB": finB},
}
print(json.dumps(out, indent=1))

What I would argue against

“In-silico screening can replace the assay once the predictor is good enough.” The toy says the failure is not accuracy in-sample but selection-induced drift: any greedy loop actively mines the predictor’s errors, so the better the loop performs on score, the more the delivered protein lags the prediction — closing the loop in the computer amplifies exactly the bias it cannot see. “So compute loops are useless.” Also wrong, and Figure 1 is the counterexample in miniature: loop B uses the same biased predictor and still wins, because the assay breaks the feedback at the right place — the predictor proposes, the experiment disposes1,3. The right reading of “success rate needs a denominator” is therefore not “distrust models” but “match the loop to the quantity you actually need to maximise”.
