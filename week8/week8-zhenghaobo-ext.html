Week 8 — Extension: 42.5% recovery is 3.9× a burial-composition rule

Author: Zheng Haobo · Week 8 (2026-11-09) · CCBS 2026

One sentence: The eight designs average 42.53% recovery, 3.93× a rule given only burial class and class composition — an increment over the rule, not a recapitulation of nature, and not separable here from training-set memory.

The point I am adding

The Lecture 15 page reports one number: its first saved ProteinMPNN sequence, T0.1-S1, matches 39 of the 92 positions, 42.4%. The eight designs average 42.53%, and that batch is what this essay measures. Missing is what a rule recovers when told only each position's burial class and that class's composition — not the residue at any position.

Let L = 92 and index the positions i = 1…L. For a design d and the input s, recovery is

rec(d)=1LLΣi=11[di=si].

The only structural quantity used is burial: bi counts Cα atoms within 8.0 Å of Cα i, skipping |i − j| ≤ 2. The classes are core bi ≥ 8 (22 positions), boundary 5–7 (31), surface ≤ 4 (39); these cut-offs are my proxies — Cα only, no side chains or solvent accessibility, and not ProteinMPNN's burial measure — fixed before any recovery is computed.

Three baselines use two information sets. Let fa be the input frequency of amino acid a. The global rule draws independently from these frequencies. The class rule also knows each position's burial class c and draws from its input frequencies fa|c. Class MAP uses the same information but always chooses the most frequent residue. Their expectations are

Eglobal=Σafa2=7.37%Eclass=ΣcwcΣafa|c2=10.81%, EMAP=Σcwcmaxafa|c=18.48%.wc=nc92

Each position contributes the input frequency of its own residue, fsi; averaged over the 92 positions that is Σa fa2, the global expectation, and conditioning on the class repeats the same sum inside each class.

The eight designs (checkpoint v_48_020, seed 37, two temperatures, four sequences each) span 40.22–46.74%, the first recovering 42.39% (the page's 42.4%). Against the burial-class expectation the batch is 3.93×; against global composition, 5.77×; against class MAP, 2.30×.

By class, core recovers 63.07% against 13.22% (4.77×), boundary 36.69% against 9.05% (4.05×), surface 35.58% against 10.85% (3.28×). The surface also exceeds its class expectation, so the excess is present in all three burial classes, not confined to the core.

The class rule alone accounts for 10.81/42.53 = 25.4% of the observed number — a ratio of two numbers, not a decomposition of the other three quarters. The reference makes training data concrete: the input is Top7, a 2003 computational design whose sequence RosettaDesign chose on a Rosetta-searched backbone, and the data field's native is not a provenance claim. The page adds that the input is not held out and may overlap a model's training data.

Read the ratio the other way first: 10.81% is what this crude rule already gets, so 42.53% exceeds that baseline — an increment over composition and burial class, not evidence of a large absolute skill. What that increment is made of — structure, training-set memory, or both — this comparison cannot say.

Input: one 92-residue experimental backbone (PDB 1QYS, chain A, residues 3-94,
C-alpha atoms only) and the eight sequences ProteinMPNN proposed for it.
Recovery of a design is the fraction of the 92 positions where it equals the
input sequence.  Three expectations are computed for rules that use the input
composition, optionally conditioned on burial class:

    global composition    sum_a f_a^2
    burial class          sum_c w_c * sum_a f_{a|c}^2
    burial class + MAP    sum_c w_c * max_a f_{a|c}

where f_a is the input's amino-acid composition, f_{a|c} the composition inside
burial class c, and w_c = n_c / 92.

Burial of position i is the number of C-alpha atoms within 8.0 A of i whose
sequence separation |i - j| exceeds 2.  Classes: core b >= 8, boundary
5 <= b <= 7, surface b <= 4.

Standard library only.  No arguments, no file access, no network.  The script
prints exactly one JSON object: the numbers, and a two-panel SVG drawn from
those same numbers.

Coordinates are stored as integers in units of 0.001 A, so every published

def burial_counts(coords, cutoff=CA_CUTOFF, min_separation=MIN_SEQUENCE_SEPARATION):
    """Per position: C-alpha neighbours within `cutoff` A, skipping |i - j| < min_separation."""
    cut2 = cutoff * cutoff
    counts = []
    for i, (xi, yi, zi) in enumerate(coords):
        n = 0
        for j, (xj, yj, zj) in enumerate(coords):
            if abs(i - j) < min_separation:
                continue
            dx, dy, dz = xi - xj, yi - yj, zi - zj
            if dx * dx + dy * dy + dz * dz <= cut2:
                n += 1
        counts.append(n)
    return counts


def classify(burial, core_min=CORE_MIN, boundary_min=BOUNDARY_MIN, boundary_max=BOUNDARY_MAX):
    """core / boundary / surface label for every position."""
    labels = []
    for b in burial:
        if b >= core_min:
            labels.append("core")
        elif boundary_min <= b <= boundary_max:
            labels.append("boundary")
        else:
            labels.append("surface")
    return labels


def positions_of(labels, name):
    return [i for i, lab in enumerate(labels) if lab == name]


def composition(sequence, positions):
    """Amino-acid frequencies over the given positions."""
    counts = {}
    for i in positions:
        counts[sequence[i]] = counts.get(sequence[i], 0) + 1
    n = len(positions)
    return {a: c / n for a, c in counts.items()}


def expected_global(native):
    """Designer knows only the input's total composition: sum_a f_a^2."""
    f = composition(native, range(len(native)))
    return sum(v * v for v in f.values())


def expected_by_class(native, labels):
    """Designer also knows each position's burial class: sum_c w_c * sum_a f_{a|c}^2."""
    total, per_class = 0.0, {}
    for c in CLASSES:
        pos = positions_of(labels, c)
        f = composition(native, pos)
        per_class[c] = sum(v * v for v in f.values())
        total += (len(pos) / len(native)) * per_class[c]
    return total, per_class


def expected_map(native, labels):
    """Designer uses the same class frequencies but always chooses their mode: sum_c w_c * max_a f_{a|c}."""
    total, per_class = 0.0, {}
    for c in CLASSES:
        pos = positions_of(labels, c)
        f = composition(native, pos)
        per_class[c] = max(f.values())
        total += (len(pos) / len(native)) * per_class[c]
    return total, per_class


def same_positions(design, native):
    return sum(1 for a, b in zip(design, native) if a == b)


def observed_by_class(designs, native, labels):
    """Fraction of (design, position) pairs inside each class that match the input."""
    per_class = {}
    for c in CLASSES:
        pos = positions_of(labels, c)
        hits = sum(1 for d in designs for i in pos if d[i] == native[i])
        per_class[c] = hits / (len(pos) * len(designs))
    return per_class


def pearson(xs, ys):
    """Product-moment correlation."""
    n = len(xs)
    mx, my = sum(xs) / n, sum(ys) / n
    sxy = sum((x - mx) * (y - my) for x, y in zip(xs, ys))
    sxx = sum((x - mx) ** 2 for x in xs)
    syy = sum((y - my) ** 2 for y in ys)
    return sxy / math.sqrt(sxx * syy)


def sensitivity(burial, native, mean_recovery):
    """Expectation and ratio when the class cutoffs move.

    slide_all_cutoffs shifts core, boundary and surface together (core >= t,
    boundary t-3..t-1, surface <= t-4); slide_core_only keeps the surface cut at
    b <= 4 and moves only the top of the boundary band (core >= t, boundary
    5..t-1).
    """
    rows = []
    for t in (7, 8, 9):
        for rule, lo, hi in (("slide_all_cutoffs", t - 3, t - 1),
                             ("slide_core_only", BOUNDARY_MIN, t - 1)):
            labels = classify(burial, t, lo, hi)
            counts = {c: labels.count(c) for c in CLASSES}
            zero, _ = expected_by_class(native, labels)
            rows.append({"rule": rule, "core_min": t, "counts": counts,
                         "zero_model_pct": round(100 * zero, 4),
                         "ratio": round(mean_recovery / (100 * zero), 4)})
    return rows

def main():
    native = NATIVE
    length = len(native)
    designs = [seq for _, _, seq in CANDIDATES]
    for seq in designs:
        if len(seq) != length:
            raise ValueError("design length differs from the input")

    coords = [(x / 1000.0, y / 1000.0, z / 1000.0) for x, y, z in COORDS_MILLI]
    burial = burial_counts(coords)
    labels = classify(burial)
    counts = {c: labels.count(c) for c in CLASSES}

    global_zero = expected_global(native)
    class_zero, class_zero_by_class = expected_by_class(native, labels)
    map_zero, map_zero_by_class = expected_map(native, labels)
    observed_class = observed_by_class(designs, native, labels)

    per_design = [{"id": cid, "score": score, "same": same_positions(seq, native),
                   "pct": round(100 * same_positions(seq, native) / length, 4)}
                  for cid, score, seq in CANDIDATES]
    recoveries = [d["pct"] for d in per_design]
    # The mean is taken over the eight full sequences, not over the rounded values.
    mean_recovery = 100 * sum(d["same"] for d in per_design) / (len(per_design) * length)

    same_across_all = [i for i in range(length) if len({seq[i] for seq in designs}) == 1]
    same_as_input_always = [i for i in range(length) if all(seq[i] == native[i] for seq in designs)]
    same_as_input_by_class = {c: sum(1 for i in same_as_input_always if labels[i] == c) for c in CLASSES}

    correlation = pearson([d["score"] for d in per_design], recoveries)

    numbers = {

What I would argue against / where this breaks

I would argue against two claims this number is often asked to support. First, that 42.53% shows the network learned to recapitulate natural sequences: the reference is designed and the input is not held out, so that is untested here. Second, that 3.93× identifies what the network knows about local structure: the baselines use only composition and burial class, so the ratio is a distance from a crude rule, not an attribution.

Where it breaks. Burial is a Cα proxy: side chains or solvent accessibility could change the classification, and the overall ratio changes little when the cut-off moves (the embedded script prints that check); a different burial measure has not been tested here. The compositions are supplied from this same input, so these are descriptive baselines, not held-out predictions. The reference may also overlap the training data, so this comparison cannot separate generalization from training-set memory. Recovery is not folding or function either: the eight sequences have no structure or function test. Recovery numbers are also benchmark-dependent: the published 52.4% against 32.9% on 402 monomer backbones is a different design protocol, not this batch. None of this says the designs fail; it says what the number can be evidence for.

What would change the reading: a null conditioning on more than burial — local secondary structure, a sequence profile — or a held-out backbone unrelated to any training entry. Without one, the increment is only a distance from the rule it is measured against.
