WEEK 3 — Extension: Fast and slow weights

Author: Weihan Luo · Week 3 (2026-09-21) · CCBS 2026

One sentence: Fast weights in a learning system can be treated as an almost-instantaneous memory only when they adapt much faster than the slow weights that learn longer-term structure.

The point I am adding

Lecture 6 introduces singular perturbation: a system can contain a fast variable and a slow variable at the same time. The fast variable adjusts quickly, while the slow variable changes gradually. If the timescale ratio ε is very small, we can approximate the fast variable as already adjusted to the current slow state. This can reduce a complicated dynamical system to a simpler one.

This idea has a useful connection to Jimmy Ba and colleagues' work on fast weights. In their neural-network model, fast weights respond to recent inputs and provide temporary memory, while ordinary weights change more slowly and store persistent regularities. The names are not accidental: both systems separate short-lived adaptation from long-lived structure.

But the connection is a condition, not a free simplification. A fast-weight model can be approximated by a slow model only if the fast weights really have time to track the current input before the slow weights move substantially. If the two update speeds become similar, the fast weights carry their own transient history, and deleting them can change the model's behavior.

Work it

Consider a deliberately simple learning system. Let s be a slow weight and f be a fast weight. The slow weight moves toward a target, while the fast weight tries to track the current slow state:

ds/dt = 1 − s
ε df/dt = s − f

When ε is small, f quickly approaches s. The fast weight then looks like an instantaneous memory of the slow state. When ε = 1, the two variables move on the same clock and the tracking approximation is visibly worse.

The small-ε curve supports the reduction f ≈ s: after a short transient, the two variables are nearly indistinguishable. The ε = 1 curve is a counterexample to treating every fast-looking variable as already equilibrated. The approximation is useful because of a measured timescale separation, not because the word “fast” appears in the model description.

Reproduce the figure 
def simulate(epsilon, dt=0.002, end=5):
    s, f = 0.0, 0.0
    rows = []
    for step in range(int(end / dt) + 1):
        t = step * dt
        rows.append((t, s, f))
        ds = 1.0 - s
        df = (s - f) / epsilon
        s += dt * ds
        f += dt * df
    return rows

slow_fast = simulate(0.05)
same_speed = simulate(1.0)

What I would argue against / where this breaks

Fast and slow weights are not identical to a biochemical enzyme and substrate. Ba et al.'s fast weights are a machine-learning memory mechanism, while Lecture 6 studies differential equations motivated by biological reactions. Also, a real neural network may have many interacting weights, noisy gradients, changing inputs, and no single fixed value of ε.

Even so, the shared lesson is precise: reducing a system by removing fast variables requires a timescale check. If the fast memory is updated quickly enough, it can be summarized by the current slow state. If not, its transient history is part of the computation and must be retained.
